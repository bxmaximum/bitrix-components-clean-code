# Lesson 01: Legacy-компонент (исходная версия)

Это типичный компонент, написанный в стиле 2015 года. Он работает, но содержит множество архитектурных проблем.

## Антипаттерны в этом компоненте

### component.php

| # | Проблема | Строка | Последствия |
|---|----------|--------|-------------|
| 1 | Глобальные переменные | 21 | Неявные зависимости, сложно тестировать |
| 2 | Нет валидации параметров | 24-26 | Возможны ошибки при неверных данных |
| 3 | Старый API `CModule::IncludeModule` без проверки | 29 | Нет D7, падение на неизвестном классе |
| 4 | Ручное кэширование без учёта пользователя | 33-36 | Cache Poisoning |
| 5 | `CIBlockElement::GetList` вместо ORM | 57-63 | Устаревший API, нет типизации |
| 6 | N+1: свойства и автор в цикле | 67, 80-85 | На 50 новостях — 101 запрос из этого файла |
| 7 | Смешение логики и форматирования | 69-77 | Нарушение SRP |
| 8 | SEO захардкожен | 108-112 | Нельзя переиспользовать |

### template.php

| # | Проблема | Строка | Последствия |
|---|----------|--------|-------------|
| 1 | Запросы к БД в шаблоне | 43-50, 74-77 | N+1, нарушение MVC |
| 2 | Бизнес-логика (`$USER->IsAdmin()`) | 65 | Шаблон не должен принимать решения |
| 3 | Inline-стили | везде | Невозможно переопределить |
| 4 | Нет экранирования | 30, 34, 57 | XSS-уязвимость |

## Как проверить проблемы

1. Отключите кэш и откройте страницу с `?show_sql_stat=Y` под администратором
2. В «Статистике SQL-запросов» посчитайте строки с трассировкой на файлы компонента
3. При 10 новостях выйдет 32 запроса, если новости завели вы сами, и 41, если их автор — другой пользователь (`CUser::GetByID()` не ходит в базу за текущим пользователем)
